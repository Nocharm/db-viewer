db-viewer 사용 안내

사내 데이터베이스의 테이블·뷰가 무엇이 있고 서로 어떻게 이어지는지 찾아보고, 실제 값을 미리 보고, 화면에서 본 값이 어느 컬럼에 저장돼 있는지 역추적하는 도구입니다. 이 문서는 처음 쓰는 사람도 따라 할 수 있게 화면별로 하나씩 설명합니다.

대상: db-viewer에 로그인해 데이터를 찾아보는 모든 사용자 (관리자 절은 9장) 기준 버전: 2026-09-11 (값 추적·뷰 쿼리 보기 포함) 이 파일은 화면 우측 상단 「사용 안내」 버튼으로 언제든 다시 받을 수 있습니다

1시작하기 — 로그인과 공통 화면

1-1. 로그인

브라우저로 db-viewer 주소에 접속하면 로그인 화면이 나옵니다. 회사 설정에 따라 두 가지 중 하나 또는 둘 다 보입니다.

  • Keycloak(SSO) — 들어가자마자 자동 로그인을 한 번 시도합니다(로그인 확인 중…). 안 되면 Keycloak으로 로그인 버튼을 누릅니다. 로그인 후 원래 가려던 주소로 돌아갑니다.
  • LDAP(사번) — 사번과 비밀번호를 넣고 로그인. 틀리면 빨간 한 줄이 뜨고 비밀번호 칸은 비워집니다.
"접근 권한이 없습니다"가 뜨면 로그인은 됐지만 아직 화이트리스트에 등록되지 않은 계정입니다. 화면의 안내대로 관리자에게 등록을 요청하세요. 관리자는 관리 콘솔의 「로그인 화이트리스트」 또는 「AD 사용자」 목록에서 추가합니다.

1-2. 화면 상단(헤더)에 늘 있는 것

요소설명
DB-viewer 로고누르면 처음 화면으로 돌아가며 검색어·필터·선택이 모두 초기화됩니다.
메뉴 테이블 · 조인 검증 · ERD · 값 추적 · 파싱 지표화면 이동. 사내 MSSQL이 아닌 소스(PostgreSQL·SQLite)를 보고 있으면 조인 검증과 파싱 지표는 숨겨집니다. 그 두 기능은 MSSQL 전용입니다.
메뉴 관리시스템 관리자에게만 보입니다.
소스 선택(드롭다운)여러 DB가 등록된 경우에만 나타납니다. 바꾸면 그 DB 기준으로 목록·미리보기가 전부 새로 시작되고, 주소에 ?source=가 붙어 새로고침해도 유지됩니다.
말풍선 아이콘 (스키마 Q&A)MSSQL 소스에서만. 자연어로 "수주와 출하를 잇는 테이블은?" 같은 질문을 할 수 있습니다(8장).

2알아두면 좋은 말들

화면 곳곳에 나오는 낱말입니다. 비유로 먼저 잡아두면 나머지가 쉬워집니다.

카탈로그 · 스냅샷
DB의 "재고표"입니다. 어떤 테이블에 어떤 컬럼이 있고 행이 몇 개인지 미리 수집해 둔 것이고, 수집 1회분을 스냅샷이라고 부릅니다. db-viewer는 대부분의 화면을 이 재고표만으로 그립니다. 실제 값을 읽는 건 "미리보기"와 "값 추적"뿐입니다.
스키마
테이블을 묶는 상자입니다. 이 회사에서는 스키마가 곧 시스템(예: SAP, ATM, BCMS)이라, "어느 시스템의 데이터인가"를 고르는 단위로 생각하면 됩니다.
테이블 · 뷰
테이블은 값이 실제로 저장되는 서랍, 뷰는 여러 서랍을 골라 보여주는 "창문"입니다. 화면에는 T/V 배지로 구분됩니다. 뷰는 SQL로 정의되며 「쿼리 보기」로 그 SQL을 읽을 수 있습니다.
계보(lineage)
뷰가 어느 테이블을 읽는지 거슬러 올라간 것입니다. "이 뷰의 이 컬럼은 저 테이블의 저 컬럼에서 왔다"까지 풀려 있으면 direct, 계산식이면 derived입니다.
FK · 관계 · 조인 키
두 테이블을 잇는 열쇠입니다. DB에 선언된 FK는 13개뿐이라, 나머지는 db-viewer가 조인 검증으로 찾아 "관계"로 기록합니다. 여러 테이블에서 반복되는 열쇠 컬럼을 조인 키라고 부릅니다.
containment(포함률)
"출발 테이블의 값이 대상 테이블에 몇 % 있나"입니다. 100%에 가까울수록 진짜 이어진 관계입니다.
미리보기 허용 스키마
실제 값을 볼 수 있게 관리자가 열어 둔 스키마 목록입니다. 목록에 없는 스키마는 구조는 보이지만 값은 볼 수 없고, 버튼이 잠깁니다.
컬럼 비공개 스키마
서버 설정으로 컬럼조차 감춘 스키마입니다. 이름만 목록에 보이거나 아예 안 보이고, 그 테이블로는 이동할 수 없습니다.
마스킹
미리보기에서 ●●●로 가려지는 컬럼입니다. 값 추적에서도 검색 대상에서 빠집니다.
감사 로그
누가 언제 어느 테이블의 실제 값을 봤는지 남는 장부입니다. 미리보기·조인 샘플·값 추적이 전부 기록됩니다.

3테이블 브라우저 /

기본 화면입니다. 위에서 아래로 JOIN KEYS 바 → 세 칸(왼쪽 레일 · 테이블 목록 · 테이블 상세) → (열었을 때) 미리보기 순서로 놓여 있습니다.

3-1. JOIN KEYS 바 (맨 위 칩 줄)

  • FK·뷰 JOIN·확정된 관계에서 모은 조인 키가 칩으로 늘어섭니다. 칩의 숫자는 그 키를 가진 테이블 수입니다.
  • 칩을 누르면 그 키로 조인되는 테이블만 목록에 남습니다. 다시 누르면 해제. 전체가 기본입니다.
  • 많으면 12개까지만 보이고 +N으로 펼칩니다.

3-2. 왼쪽 레일 — 카테고리 / DB

  • 카테고리 탭: 업무 분류(테이블명 접두어 기준)로 목록을 좁힙니다. 이름 옆 자물쇠는 미리보기 허용 여부입니다(열림 = 허용 스키마 포함, 잠김 = 미허용).
  • DB 탭: 스키마(=시스템)마다 체크박스가 있어 보고 싶은 DB만 체크해 둘 수 있습니다. 이 체크는 내 브라우저에만 저장됩니다. 필터 해제 / 전체 선택으로 한 번에 바꿉니다.
  • DB 탭에서 스키마 옆 카테고리 칩을 누르면 그 자리에서 카테고리 이름을 바꿀 수 있습니다(Enter 저장, Esc 취소). 이 변경은 모든 사용자에게 공통이니 이름은 신중히.
  • 레일과 목록 사이 경계를 드래그하면 폭이 바뀝니다.

3-3. 테이블 목록

  • 검색창에 테이블명·컬럼명·카테고리 어느 것이든 입력하면 됩니다. 초성 검색이 됩니다(ㅍㅈ → 품질). 컬럼명으로 걸린 경우 행 아래에 컬럼: …이 표시됩니다.
  • 전체 · 테이블 · 뷰 칩으로 종류를 거릅니다. 행 오른쪽 20c는 컬럼 수입니다.
  • 회색으로 비활성인 행(컬럼 비공개 배지)은 서버가 컬럼을 감춘 스키마라 들어갈 수 없습니다.
  • 목록은 100개씩 이어서 불러옵니다. 스크롤을 내리면 더 나옵니다.

3-4. 테이블 상세

목록에서 하나를 누르면 오른쪽에 상세가 뜹니다. 위에서부터:

  1. 이름 + TABLE/VIEW 배지 + N rows · M columns. 미리보기가 열려 있으면 미리보기로 ↓로 바로 내려갈 수 있습니다.
  2. AI 요약 / AI 설명(MSSQL만): AI 요약 생성, 뷰라면 AI 설명. 사내 LLM이 연결돼 있지 않으면 AI 미연결 — 목업 배지가 붙은 예시 문장이 나옵니다.
  3. 주 버튼 — 값을 보는 버튼은 왼쪽, 다른 화면으로 나가는 버튼은 오른쪽 끝에 있습니다.
    • 미리보기 TOP 20 — 실제 값을 화면 아래에 엽니다(4장). 미허용 스키마면 잠겨 있고 옆에 미리보기 미허용이 표시됩니다.
    • 쿼리 보기(뷰만) — 뷰 정의 SQL을 바로 아래 패널로 펼칩니다(3-5).
    • ERD 보기 →(오른쪽 끝) — 이 테이블에 포커스한 ERD로 이동합니다.
  4. 컬럼 (N) — 컬럼 칩 목록. PK 마크, 초록 테두리는 조인 키입니다. 기본 2줄만 보이고 컬럼 더보기로 펼칩니다. 칩을 누르면 조인 검증 화면으로 넘어가 그 컬럼이 출발 컬럼으로 미리 채워집니다.
  5. 조인 가능성 찾기(테이블·MSSQL만) — 후보 일괄 검증을 누르면 이 테이블과 이어질 법한 다른 테이블들을 실제 값으로 한꺼번에 검사해 포함률 %와 함께 보여줍니다. 마음에 드는 행은 빌더에 추가로 조인 검증에 그대로 넘깁니다.
  6. 구성 테이블 (lineage)(뷰만) — 이 뷰가 읽는 테이블. depth는 몇 단계 아래인지입니다.
  7. 이 테이블을 사용하는 뷰 — 반대 방향 계보.
  8. 유사 테이블(테이블만) — 컬럼명이 30% 이상 겹치는 테이블. 행의 검증으로 단건 검사.
  9. FK 관계 — DB에 선언된 외래키. → 나가는 것, ← 들어오는 것.
  10. 추론·확정 관계 — db-viewer가 찾아 기록한 관계. ✓는 확정, 추정은 아직 확정 전, N:M은 카디널리티, 숫자는 confidence입니다.

상세 안의 테이블 이름은 모두 클릭하면 그 테이블로 이동합니다.

3-5. 뷰 「쿼리 보기」

  1. 뷰를 선택하고 쿼리 보기를 누릅니다.
  2. 버튼 아래에 뷰 정의 SQL 패널이 열립니다. 예약어(파랑)·함수(주황)·문자열(초록)·숫자(보라)·주석(회색 기울임)이 각각 다른 색이고, 테이블·컬럼 이름은 본문색입니다. 색은 단어 단위로만 칠해져 EQUIS 안의 IS나 ISNULL 안의 NULL이 따로 물들지 않습니다.
  3. 복사로 SQL 전체를 클립보드에 복사합니다(복사됨 표시). ×로 닫습니다.
정의가 안 보이면 "정의가 수집되지 않았다 — 원본 DB의 VIEW DEFINITION 권한 확인"이 뜹니다. 카탈로그를 수집할 때 원본 DB가 뷰 정의를 내주지 않은 경우이며, 화면 문제가 아니라 권한 문제입니다. 컬럼 비공개 스키마의 뷰는 버튼이 잠깁니다.

4미리보기 (값 보기)

미리보기는 테이블·ERD·조인 검증 세 화면이 같은 부품을 씁니다. 한 번 익히면 어디서나 같습니다. 열 때마다 원본 DB에 새로 질의하므로, 조건을 바꾸면 조회를 눌러야 반영됩니다.

4-1. 탭 바

  • 여는 테이블마다 탭이 생깁니다. 탭 이름 클릭 = 전환, × = 닫기.
  • 분할 — 탭이 둘 이상이면 두 테이블을 좌우로 나란히 놓습니다(조인 검증에서 특히 유용). 단일로 되돌립니다.
  • 줄바꿈 / 말줄임 — 긴 값을 접을지 줄바꿈할지.
  • 위로 — 테이블 상세로 다시 올라갑니다.

4-2. 필터 거는 법 (조건은 AND로 결합)

  1. 필터 컬럼 선택에서 컬럼을 고릅니다.
  2. 연산자를 고릅니다.
    연산자뜻예
    부분 일치이 글자를 포함kim → "KIMCHI", "Mr. Kim" 모두
    정확 일치정확히 이 값(대소문자 무시)PAID → "paid"도 잡힘
    부분 제외이 글자를 포함하지 않음(빈 값 포함)
    정확 제외 (≠)이 값이 아님(빈 값 포함)
    비어 있음 (NULL)값이 없음값 입력 불필요
    값 있음 (NOT NULL)값이 있음값 입력 불필요
  3. 값을 입력합니다. 이미 불러온 행의 고유값이 자동완성으로 뜹니다. Enter 또는 필터 추가로 칩을 만듭니다.
  4. 칩이 점선 테두리면 아직 적용 전입니다. 조회를 누르면 원본에 다시 질의하고 칩이 실선으로 바뀝니다.
  5. 칩의 ×로 하나 빼거나 필터 해제로 전부 지웁니다. 조건은 최대 5개입니다.
빠른 길 표의 셀을 더블클릭하면 그 값으로 "정확 일치" 칩이 바로 만들어집니다(빈 셀은 NULL 조건). 셀을 우클릭하면 복사 · 이 값만 보기 · 이 값 제외하기 메뉴가 떠서 제외 조건도 바로 걸 수 있습니다. 그 다음 조회만 누르면 됩니다.

기억할 것 미리보기는 실제 값을 읽는 일이라 허용된 스키마에서만 열리고, 열 때마다 감사 로그에 남습니다. ●●●로 보이는 컬럼은 마스킹 정책이 걸린 것입니다.

5조인 검증 /verify (MSSQL 전용)

"이 두 테이블이 이 컬럼으로 정말 이어지나?"를 값을 읽지 않는 검사부터 비싼 검사 순으로 4단계로 확인하고, 맞으면 관계로 확정해 ERD에 그립니다.

5-1. 세 칸의 역할

왼쪽 — 선택한 테이블·컬럼출발/대상 테이블을 고르고 연결할 컬럼 페어를 정합니다. 셋이 다 정해지면 자동으로 접혀 한 줄 요약이 되고, 다시 누르면 펼쳐집니다. 그 아래 진행 순서 카드가 4단계의 상태(완료·지금 할 차례·잠김)를 보여줍니다.
가운데 — 검증 카드 4장맨 위 「지금 확인 중인 연결」에서 컬럼을 바로 갈아끼울 수 있고, 값 미리보기로 두 테이블을 분할 미리보기로 엽니다.
오른쪽 — 확인 대기 목록검증을 기다리는 후보 관계들. 항목을 누르면 왼쪽·가운데가 그 페어로 세팅됩니다. AI 관계 제안이 후보를 채워 넣습니다.

5-2. 테이블·컬럼 고르기

  1. 출발 테이블 입력칸을 누르면 스키마 목록이 펼쳐집니다. 스키마를 고르면 오른쪽에 그 스키마의 테이블이 나오고, 글자를 치면 전체에서 바로 검색됩니다. ↑↓Enter로도 고를 수 있습니다.
  2. 대상 테이블도 같은 방법으로 고릅니다.
  3. 연결할 컬럼 후보가 점수순으로 뜹니다(PK·신호 배지). 마음에 드는 걸 누르거나, 아래 직접 고르기에서 양쪽 컬럼을 직접 선택합니다.

5-3. 4단계

단계버튼무엇을 보나비용
1단계 · 빠른 점검점검 실행값을 읽지 않고 타입이 맞는지, 양쪽 컬럼이 중복투성이인지(표본 200행) 봅니다. "타입 불일치"나 "양쪽 다 값이 겹칩니다"면 여기서 멈춥니다.거의 0
2단계 · 실제 값 대조값 대조출발 값이 대상에 몇 % 있는지 실제로 셉니다. containment %, cardinality(1:1·1:N·N:M), 고아(대상에 없는 값) 건수와 처방 문장이 나옵니다.중간
3단계 · 눈으로 확인 (선택)조인 샘플 보기 외조인된 행 몇 개를 눈으로 봅니다. 출발/대상 테이블 Top 200 샘플도 따로 볼 수 있습니다. 미리보기 허용 스키마에서만.중간
4단계 · 확정관계 확정이 연결을 관계로 기록하고 ERD에 그립니다. 2단계를 마쳐야 열립니다.0
어디서 들어오나 테이블 상세의 컬럼 칩, 「조인 가능성 찾기」의 빌더에 추가, ERD 노드 우클릭 메뉴의 조인 검증하기가 모두 이 화면으로 값을 채워 넘겨 줍니다.

6ERD /erd

확정된 관계와 FK를 가진 테이블을 한 장의 그림으로 봅니다. 검증된 테이블만 그려집니다. 아직 아무 관계도 없으면 "검증된 관계가 아직 없습니다"와 조인 검증으로 가는 버튼이 나옵니다.

6-1. 화면 구성

  • 좌상단 검색 ERD에서 테이블 찾기 — 고르면 카메라가 그 노드로 이동하고 강조됩니다. 그래프에 없는 테이블은 "검증된 테이블만 그려집니다"로 안내합니다.
  • 스키마 필터(접이식) — 한 스키마만 남깁니다.
  • 노드 — TBL/VIEW 배지 + 이름 + 컬럼 수. 펼치면 컬럼 목록(PK, 계산 컬럼 ƒ, NOT NULL *).
  • 우하단 범례 — 확정(FK·사용자 확정) / 추정(검증·AI 제안) / 미검증 / 뷰 계보.

7값 추적 /trace

7-1. 무엇을 하는 화면인가

업무 화면에 ORD-0910-001 같은 값이 보이는데 DB의 어느 테이블·컬럼에 저장돼 있는지 모를 때 씁니다. 값 하나를 넣으면 db-viewer가 후보 컬럼을 고르고, 후보 테이블마다 딱 한 번씩 "이 값 있나요?"를 물어 찾은 것부터 화면에 쌓아 줍니다.

왜 스키마를 꼭 고르나 창고(DB)에 선반이 2,342개라 모든 칸에 물어보면 운영 DB가 느려집니다. 스키마가 곧 시스템이니 "어느 시스템 값인지"만 골라도 대부분을 공짜로 잘라냅니다. 나머지도 타입·길이·마스킹 같은 재고표 정보로 미리 걸러 실제 쿼리는 최소로만 나갑니다.

7-2. 따라 하기

  1. 스키마를 고릅니다. 미리보기가 허용된 스키마만 칩으로 나오며 카테고리별로 묶여 있습니다. 허용 스키마 전체 토글로 한 번에 켤 수도 있지만, 좁힐수록 빠르고 쌉니다.
  2. 필요하면 다른 스키마의 연관 뷰 포함을 켭니다(7-4).
  3. 값을 붙여 넣습니다(100자까지). 화면 라벨은 선택 사항입니다. "주문번호"처럼 화면에 적힌 이름을 넣으면 비슷한 컬럼명부터 먼저 찾습니다.
  4. 일치 기준을 고릅니다(7-3). 기본은 표기 변형 포함.
  5. 찾기를 누릅니다. 버튼이 스피너와 찾는 중 12 / 422로 바뀌고 버튼 안에 진행 바가 찹니다. 그동안 입력칸은 잠깁니다.
  6. 멈추고 싶으면 버튼 위에 마우스를 올리면 중단으로 바뀝니다. 누르면 지금 확인 중인 객체까지만 끝내고 멈춥니다. 키보드로 Enter로 시작했다면 키를 뗀 뒤 다시 Enter가 중단입니다.
  7. 찾은 컬럼 카드에 히트가 도착하는 대로 쌓입니다. 끝까지 기다리지 않아도 됩니다.

7-3. 일치 기준 3가지

기준이렇게 찾는다언제비용
표기 변형 포함
(기본)		대소문자·앞뒤 공백·구분자 차이, 1,000↔1000, 2026.09.10↔2026-09-10↔20260910, 전화번호 하이픈 유무 같은 표기만 다른 값을 함께 찾습니다.화면 값이 DB 원본과 포맷이 다를 수 있을 때(대부분)싸다 — 인덱스를 탑니다
정확히입력한 그대로만.값이 정확히 같다고 확신할 때, 결과를 좁히고 싶을 때싸다
부분 일치이 글자를 포함하는 값(LIKE '%값%').값이 잘렸거나 합쳐져 보일 때비싸다 — 모든 후보를 처음부터 끝까지 읽습니다. 그래서 후보 객체 20개 이하일 때만 허용됩니다. 넘으면 "범위를 좁혀라"는 오류가 뜹니다.
한계 표기 변형은 대문자·소문자·원문·trim 등 몇 가지 형태만 시도합니다. oRd-0910처럼 임의로 섞인 대소문자는 못 잡습니다. 그런 값은 부분 일치를 쓰되 스키마를 최대한 좁히세요.

7-4. 연관 뷰 포함

고른 스키마의 테이블을 읽는 다른 스키마의 뷰까지 후보에 넣습니다. 뷰는 값을 "가공"해서 보여주는 경우가 있어(코드→이름, 날짜 포맷, 두 컬럼 합치기) 원본 테이블에는 없는 형태가 뷰에만 있을 수 있습니다.

  • 그 뷰의 스키마도 미리보기 허용이고 비공개가 아닐 때만 검색합니다. 값을 실제로 읽는 일이라 같은 규칙을 지킵니다.
  • 규칙에 걸려 뺀 뷰는 조용히 사라지지 않고 진행 카드에 연관 뷰 +3 · 제외 2 ⓘ처럼 표시됩니다. ⓘ에 마우스를 올리면 어떤 뷰가 왜 빠졌는지(허용 목록 밖 / 숨김 스키마) 목록이 뜹니다. 10개까지 보이고 나머지는 외 N개입니다.
  • 이 옵션은 뷰 계보가 수집된 MSSQL 소스에서 의미가 있습니다. PostgreSQL·SQLite는 계보가 없어 0개입니다.

7-5. 진행 카드 읽기

  • 상태 배지: 대기 · 실행 중 · 완료 · 실패 · 취소됨.
  • 스탯 필: 후보 객체(실제로 쿼리를 보낼 테이블·뷰 수) · 컬럼(검사하는 컬럼 수) · 무거운 객체(자동 실행에서 뺀 수) · 연관 뷰(켰을 때).
  • 진행 바 아래 12 / 422와 지금 확인 중: SAP.T_ORD · 8s. 대략 몇 초에 몇 개를 훑는지로 남은 시간을 가늠할 수 있습니다.

7-6. 찾은 컬럼 카드

행 하나가 히트 하나입니다: 테이블/뷰 배지 · 스키마.객체 · 컬럼 칩 · 건수.

  • 건수는 1000까지만 셉니다(넘으면 1000+). 무거운 객체를 선택 실행한 경우엔 건수 대신 확인됨입니다.
  • 입력값과 저장 형태가 다르면 저장 형태 1000처럼 실제로 맞은 모양을 알려줍니다.
  • 미리보기 열기 — 테이블 화면이 열리면서 그 컬럼 = 실제 저장값 필터가 이미 걸린 미리보기가 뜹니다. 입력한 값이 아니라 "저장 형태"로 필터를 걸어 주니 바로 행이 보입니다.
  • 쿼리 보기(뷰 히트만) — 행 아래에 뷰 정의 SQL이 펼쳐지고 히트한 컬럼이 강조 배경으로 표시됩니다. 헤더에 히트 컬럼: RELATED_CD 칩이 붙고, 아래에 원본: dbo.APV_APRV.APRVCD처럼 이 컬럼이 어느 테이블에서 왔는지도 같이 보여줍니다. 여러 뷰를 동시에 펼쳐 비교할 수 있습니다.
  • 노출하는 뷰 N — 테이블 히트일 때, 이 컬럼을 그대로 내보내는 뷰 목록을 접이식으로 보여줍니다. "화면은 아마 이 뷰를 읽고 있겠구나"를 짐작하는 데 씁니다.
  • 오류·타임아웃 대상 N — 쿼리가 실패한 객체 목록. 잡 전체는 계속 진행됩니다.

다 돌았는데 하나도 없으면 선택한 스키마에서 찾지 못했다와 함께, 아직 안 본 허용 스키마가 남아 있으면 나머지 허용 스키마로 계속 버튼이 나옵니다. 자동으로 범위를 넓히지 않고 사용자가 누를 때만 넓힙니다.

7-7. 무거운 객체 카드

행 수가 200만을 넘거나 행 수를 모르거나(계보가 안 풀린 뷰), 집계·DISTINCT·UNION 같은 무거운 뷰는 자동 실행에서 뺍니다. 한 번의 조회가 운영 DB에 부담을 줄 수 있기 때문입니다.

  • 사유 배지: 행 수 초과(주황) · 행 수 미상(회색) · 집계·DISTINCT 뷰(보라). 옆에 추정 행 수.
  • 꼭 봐야 하는 객체만 체크하고 선택 실행. 체크가 곧 "비용을 감수하겠다"는 승인입니다. 잡이 도는 동안은 버튼이 잠기니 끝난 뒤에 누르세요.

7-8. 팁과 규칙

  • 스키마를 좁히는 것이 가장 큰 절약입니다. 시스템을 안다면 그 스키마 하나만 고르세요.
  • 검색은 미리보기 허용 스키마 안에서만 됩니다. 원하는 스키마가 목록에 없으면 관리자에게 허용 요청을 하세요.
  • 마스킹된 컬럼, 컬럼 비공개 스키마, 모든 테이블이 히트할 법한 저카디널리티 컬럼(USE_YN류)은 후보에서 빠집니다.
  • 한 번의 검색은 감사 로그에 남습니다(소스·스키마·값·대상 수). 결과는 검색한 본인과 관리자만 볼 수 있습니다.
  • MSSQL 소스에서 한 쿼리의 시간 상한은 n8n 연결 설정(requestTimeout)이 정합니다. 시간이 초과되면 그 객체만 timeout으로 기록되고 다음으로 넘어갑니다.

8파싱 지표 · 스키마 Q&A

8-1. 파싱 지표 /parsing (MSSQL 전용)

뷰 정의 SQL을 얼마나 해석했는지 보여줍니다. 큰 숫자가 파싱 성공률이고, 타일에 전체 뷰 · 파싱 성공 · 부분 해석 · 미지원 · 파싱 실패 · 정의 없음(권한)이 나옵니다. 아래 표의 뷰 이름을 누르면 그 뷰의 상세로 이동합니다. 계보가 안 풀린 뷰는 값 추적에서 행 수 미상으로 무거운 객체에 들어가니, 여기서 원인을 확인할 수 있습니다.

8-2. 스키마 Q&A (헤더 말풍선 아이콘, MSSQL 전용)

"수주와 출하를 잇는 테이블은?"처럼 자연어로 물으면 AI가 스키마 정보를 바탕으로 답합니다. 답변에 붙는 테이블 칩을 누르면 ERD의 그 테이블로 이동합니다. LLM이 연결돼 있지 않으면 AI 미연결 — 목업 응답 배지가 붙습니다. 대화는 브라우저에 저장됩니다.
